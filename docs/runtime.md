# 会话 runtime 与长期记忆

普通启动创建新会话；`--resume <id>` 显式恢复。会话绑定启动时固定的规范项目根，根不匹配会拒绝恢复。恢复只加载记录，Bash 使用新进程；变量、函数、作业与实时机器状态需重新获取。进程内 `:session new/resume` 不修改 Bash，也不重放命令或复用历史确认。

## 交互入口

```text
:session list
:session new
:session resume <id>
:session show [id]
:session delete <id>
:context
:memory list [user|project|machine|all]
:memory show <id>
:memory add user language 请用中文回答
:memory add project build 使用 make build 构建
:memory update <id> 修正后的内容
:memory forget <id>
```

会话列表只显示当前项目，最多 100 项。`show` 显示完整有界原始记录。删除需确认，不能删除正在使用的会话，先切换；长期记忆保留来源 ID，即使对应会话已删除。记忆管理是用户的明确新增/修正，不能添加执行授权或凭据。列表最多 100 项，模型检索另有更小预算。记忆删除移除索引与版本内容；SQLite/WAL 不提供物理安全擦除保证。

`--ephemeral` 使用进程内连续上下文，完全不打开会话数据库、不读取/写入长期记忆、不创建或读取持久输入历史；不能与 `--resume` 同用。`--no-history` 和空 `history_file` 只关闭顶层输入历史，**会话、工具结果与记忆仍会保存**。

## 持久化与失败

数据库位于 `$XDG_STATE_HOME/lingcell/runtime.db`，未设置时为 `~/.local/state/lingcell/runtime.db`。目录 0700；数据库、WAL、SHM 和会话锁文件 0600。使用 `database/sql` + 固定版本 `modernc.org/sqlite`，不依赖 CGO；版本化事务迁移，WAL 与 `synchronous=FULL`。一个会话只有一个进程可以持有独占锁；锁文件保留避免删除重建 inode 的竞争。

记录按 Session / Turn / ToolStep 组织，包含用户请求、模型响应、工具参数、确认状态、开始和结果。模型消息最多 256 KiB，每轮归档最多 2 MiB，每会话最多 64 MiB；达到上限停止 Agent 并保留已有有界记录。每轮重新计算决策次数和项目读取预算。普通用户命令记录为已执行工具数据，不为记录额外调用模型；输入分类不进入会话历史。

Agent 的顺序是请求/响应先落盘，获批命令的开始先落盘，执行后结果落盘，才能继续决策。写入失败停止 Agent；普通用户 shell 命令仍可用，记录失败会明确提示。启动存储故障也保留普通 shell，显式恢复失败则拒绝启动该会话。未完成轮次标记中断；开始后没有可靠结果的命令标记“结果未知”，绝不自动重试。迁移损坏或未知版本不自动修复。

已知配置凭据值和可识别敏感模式在会话及输入历史写入时过滤；执行参数不受过滤影响。该过滤不保证识别任意秘密。任务内容、读取内容和命令输出会按上述预算存入用户本地数据库，请据任务内容选择临时模式。

## 上下文

`context_max_bytes` 默认 131072（128 KiB），允许 16384–2097152；按实际 Chat Completions JSON 请求体计量，包括模型名称、规则、工具定义与转义，**不是供应商 token 数**。`:context` 显示最近请求字节、预算、轮次和摘要覆盖范围。

每次决策含当前规则和新鲜运行环境、会话摘要、最近完整轮次及当前消息/工具结果；长期记忆只在本轮调用检索工具后作为工具数据进入。历史工具调用和结果保持完整配对，未处理调用补上已归档状态，不会派发执行。历史调用 ID 单独命名，避免与当前轮次重复。

超限时分批摘要较旧闭合轮次，保留最近两个完整轮次。摘要最多 16 KiB，覆盖目标、用户约束、关键发现、执行结果、失败和待办；摘要请求自身也计量预算并受超时和取消控制，不占行动决策次数。摘要失败或仍超限会停止请求，保留原始记录。当前大工具结果可缩减，明确标记截断与轮次/工具引用，不移除当前用户约束。

`read_session_history(start_turn,count,offset)` 读取当前会话归档，每次最多 32 KiB，最多 20 轮。单轮过大时返回 `record_fragment` 与 `next_offset`，使用 `count=1` 继续拼接，直至 `more=false`；`:session show` 可在终端查看完整有界记录。摘要、记忆及工具数据都不成为执行权限。

## 长期记忆

成功保存 Agent 轮次后最多一次有界提取请求，输入最多 64 KiB 且受上下文预算限制，最多 5 个候选；过大输入或提取失败显示提示，任务结果不改变，不重试。失败/中断轮次不提取，恢复和旧归档不会重新提取已删除记忆。新会话不自动注入全部记忆。

用户范围仅保存明确表达的偏好，无固定有效期；项目范围绑定规范项目根，事实默认 30 天；本机范围绑定仅本地保存的机器标识摘要，默认 7 天。内容最多 2 KiB，保存主题、类型、来源会话/轮次/消息/工具及引用、证据时间、到期、版本和状态。本机身份标识不发送模型；实时进程、端口占用和剩余空间不进入记忆。

自动候选须引用本轮真实保存记录中的文字：用户偏好来自明确用户文本；项目/机器事实来自成功执行的证据工具，不能引用模型提案、错误结果、其他记忆或历史读取工具。工具内的“请记住”不能产生用户偏好。程序校验来源/长度/类型/敏感模式；语义提取仍可能出错，用户应能查看和修正。

同主题明确新偏好更新旧版本；不同事实保留双方并标记冲突。到期显示待核实；项目再次使用相同证据工具/参数而得到不同数据时，旧事实也标记待核实。不会为了检测变化自动扫描文件或查询机器；未重新观察到的改变无法提前发现。成功新证据可恢复一致事实，冲突不会静默选择一条；用户可删改解决。

`search_memory(query,scope)` 支持 user/project/machine/all，先过滤当前范围，再按 FTS5 trigram 相关性、有效状态和更新时间排序；少于三个字符用有界字面匹配。每次最多 8 项、8 KiB，返回来源与有效状态，过期/冲突仅为待核实线索。不使用 embedding、向量库或跨用户服务。

依据：[纯 Go SQLite 驱动](https://pkg.go.dev/modernc.org/sqlite)、[SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite FTS5](https://www.sqlite.org/fts5.html)。验证结果见 [runtime 交接报告](handoffs/agent-runtime.md)。
