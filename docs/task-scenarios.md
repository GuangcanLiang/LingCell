# 通用任务场景与验证范围

同一个 Agent 使用文件工具与逐条确认的 run_command 完成以下场景。`scripts/verify_tasks.py` 提供固定临时项目、本地模拟模型和真实 CLI/PTY，接入 `make terminal`；模型根据真实工具数据断言再继续，最后只输出场景结果、模型决策次数和命令确认次数。场景失败时打印 FAIL，不把未执行项算作通过。脚本无第三方 Python 依赖，不读取个人配置或调用供应商。

## 固定场景

项目含 `src/nested/service.sh`，前120行为占位注释，第121行为 `service_port=9000`，第122行为 entrypoint 定义。端口变更目标9100，使用 Bash语法与配置断言验证；差异来自真实 diff，不预制工具结果。机器状态为固定合成文件 `LISTEN port=9000 pid=4242`，处理用无害 marker 模拟；不查询或终止真实进程。

| --- | --- | --- | --- |
| 项目理解 | 解释嵌套目录中的 entrypoint，并给出文件与行号 | 搜索定位122行，读取119至122行，回答引用依据；零命令 | 3 / 0 |

| 机器排障 | 查看模拟机器端口占用，取得状态后提出处理 | 获批状态查询返回实际合成文件内容，随后提出处理；用户拒绝后无marker、无后续模型决策 | 2 / 2（一次批准、一次拒绝） |

每次独立 CLI 结束检查终端恢复、输入历史无工具数据/生成命令；项目层 Go 回归另覆盖扫描期间取消、符号链接、私钥、UTF-8、扫描/匹配/返回上限和任务预算。`make terminal` 先保留原三独立终端会话，再运行该固定任务会话。

## 本地模拟与真实效果的门槛

模拟测试验证程序路由、参数、证据传递、确认和工具闭环；最终回答由模拟模型按已观察数据生成，不能证明真实模型会正确决策或遵循所有说明。只有完成获授权真实服务联调后，才能称“通用任务效果已验证”。本轮没有供应商、凭据或真实服务调用；原有真实模型检查点保留独立分支，不直接合入。

真实联调复用上述项目布局和目标：入口定位、错误原因、经确认修改/差异/验证、失败反馈、拒绝/取消；机器场景可先用合成状态，再在明确授权的环境查询实际状态。按场景记录候选SHA、服务/模型名称（不含凭据）、完成结果、模型决策数、确认数和失败原因；不保存原始私密提示、项目内容、模型上下文或终端输出。真实运行轮数不要求等于模拟计数；模型、服务或机器条件缺失时记未验证，不阻塞本地工具开发。
